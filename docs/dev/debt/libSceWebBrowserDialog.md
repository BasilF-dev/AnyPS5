# libSceWebBrowserDialog technical debt

### Functional

- [sceWebBrowserDialogOpen and sceWebBrowserDialogOpenForPredeterminedContent](../../../core/libs/prx/libSceWebBrowserDialog/Export.cpp) model the dialog lifecycle but do not create a host browser UI. Both complete immediately with the existing user-cancelled result. The predetermined-content signature and 424-byte allow-list layout follow [SharpProspero](https://github.com/SvenGDK/SharpProspero/blob/master/src/SharpProspero/Interop/Dialog/WebBrowserDialog.cs); up to twenty non-null domain strings are retained for the session, but no navigation occurs, so the allow-list is not enforced against network traffic. Invalid structure sizes throw because the PS5 error code for a malformed size has not been measured.
- [sceWebBrowserDialogSetCookie and sceWebBrowserDialogResetCookie](../../../core/libs/prx/libSceWebBrowserDialog/Export.cpp) use SharpProspero's 280-byte set-cookie and 264-byte reset-cookie layouts. A set call retains the URL and cookie string in the dialog's in-process session store; reset, terminate and the next initialize clear that store. The backend has no WebKit/browser engine, so stored cookies are not attached to requests. Null parameters use the common-dialog argument-null error already used by the library; malformed size error codes and console cookie parsing/replacement rules remain unverified.
